# POST /api/node/save

Pairs the device with the ParticularMatter platform using a one-time key (OTK).

On success, the device receives MQTT credentials and begins publishing sensor data automatically. Poll [`GET /api/system/status`](./system-status.md) to track the `pairingState`.

> **Prerequisite:** The device must have an active WiFi connection (`connectionState === "CONNECTED"`) before calling this endpoint.

## Request

| Field | Value |
| --- | --- |
| URL | `/api/node/save` |
| Method | POST |
| Content-Type | application/json |
| Auth | None |

### Request Body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `oneTimeKey` | String | Yes | Time-limited key generated by the ParticularMatter platform |

### Request Example

```json
{
  "oneTimeKey": "OTK-a1b2c3d4e5f6"
}
```

## Response (`data`)

```json
{}
```

## Pairing State Tracking

Pairing is asynchronous. After calling this endpoint, poll `GET /api/system/status` and observe `pairingState`:

| pairingState | Description |
| --- | --- |
| `REGISTERING` | Device is executing the pairing request in the background |
| `REGISTERED` | Pairing successful |
| `INVALID_KEY` | Server returned 400 / 401 / 403 (key invalid or expired) |
| `NETWORK_ERROR` | Server unreachable, timeout, or TLS failure |
